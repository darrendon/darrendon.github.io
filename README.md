# darrendon.github.io

Portfolio site for Darren Don, a board game designer in Kansas City. Published with GitHub Pages.

## Pages
- `/` — home: intro, games, about (design principles), let's meet (conventions), contact band
- `/games/` — every game plus the signed titles (publisher, Title TBA, player count and genre only, until each publisher announces)
- `/contact/` — contact details and quick-request email links
- `/games/dim-sum-rush/` — sell sheet, 3D component mockups, the playable build (embedded from the `dim-sum-rush` repo's Pages site at `/dim-sum-rush/`) and rules in brief
- `/games/too-many-crooks/` — rendered mockups, the playable build with online tables (hosted in this repo at `/games/too-many-crooks/play/`), sell sheet, rulebook (`rulebook.html` → `too-many-crooks-rules.pdf`; the print-and-play kit is a PDF emailed on request, with no HTML source) and rules in brief
- `/games/diggers/` — rendered mockups, the playable build against bots (hosted in this repo at `/games/diggers/play/`), the five species, sell sheet, print-and-play kit (built from `print-and-play.html`, emailed on request, not published) and rules in brief
- `/games/down-for-the-count/` — rendered mockups, the playable build against bots (hosted in this repo at `/games/down-for-the-count/play/`), the ten cards and box art, sell sheet, print-and-play kit (built from `print-and-play.html`, emailed on request, not published) and rules in brief
- `/games/un-deux-trois-cat/` — rendered mockups with the cat toys, the playable build with a tutorial and easy or hard bots (hosted in this repo at `/games/un-deux-trois-cat/play/`), the five toys and box art, sell sheet, print-and-play kit (built from `print-and-play.html`, emailed on request, not published) and rules in brief
- `/games/sentai/` — rendered mockups, the playable build with a coached tutorial, bot teammates and online tables (hosted in this repo at `/games/sentai/play/`, on the shared table in `assets/js/dev-table.js`), the cards and box art, sell sheet, rulebook, print-and-play kit (built from `print-and-play.html`, emailed on request, not published) and rules in brief. It started in In Development; the old `/in-development/sentai/` URLs redirect here
- `/in-development/` — games still being built (Abducted, Slipstream, Day One, Polar Bear Market, 2 Jibber 2 Jabble), linked from a row on `/games/`. Each page has the rules in brief, a playable build (except 2 Jibber 2 Jabble, a party game) and feedback questions that open a prefilled email to darren@darrendon.com

## In Development
- `in-development/build.py` — writes the section page and every game page from the data at its top (copy, specs, rules in brief, feedback questions). Edit there and rerun `python3 in-development/build.py`; don't hand-edit the generated `index.html` files
- `in-development/img/src/art.html` + `shoot.py` — the flat box fronts (`?g=slipstream|jibber|abducted|dayone|polar`); `python3 in-development/img/src/shoot.py [game …]` with the site served on :8123 writes each game's `img/box-front*.webp` and `img/scene*.webp`
- `assets/js/dev-table.js` + `assets/css/dev-table.css` — the shared table every In Development build uses: play vs bots, host an online table or join with a five-letter code (same public MQTT relays as Too Many Crooks!), table talk, and `DevTable.flip()` so pieces slide between positions. A game supplies `create()` (an engine with `view/act/botStep/over`) and `render()`; see the header comment
- `assets/js/dev-feedback.js` — turns each page's question list into the feedback form; answers open as an email, or copy to the clipboard
- `in-development/<game>/play/engine.js` — each build's rules engine and bots, with every tunable number in `RULES` at the top; it also runs in node, and `sim.js` beside it plays bot-only games headless (`node sim.js 3000`)
- Abducted moved back to In Development (`/in-development/abducted/`, built by `build.py`; its build still lives at `/games/abducted/play/` and the entry's `play.url` points there). `/games/abducted/` now redirects to it. The full game page was removed, but its pitch video, sell sheet, rulebook and print-and-play sources are still in `games/abducted/`

## Look
- Wordmark: Righteous (`assets/fonts/righteous.woff`, OFL) for the name in the header and the big page titles; everything else is Jost.
- Palette (`assets/css/site.css` tokens, "Palette v2" block): orange #E18C0A, periwinkle #898FA9, sand #C9B88E, olive #949015 and pink #CD9993 on warm paper #F5F3EE with ink #25272E; darker orange #A35F05 and olive #6B680E for text on paper, plus dark-mode equivalents. Game pages keep their own palettes.
- Type: Jost everywhere. `assets/css/type.css`, loaded last on game pages, applies the site type to every heading, label and button; each game keeps only its logotype (hero h1 and homepage card title) in its own face.
- Genres and other tag-style labels are Title Case without the word "game" ("Partnership Climbing", "Dexterity").
- Logo: four dice showing 1–4, one in each palette color (`assets/img/favicon.svg`, also inlined in every page's header).
- Game cards (home and /games/) share one layout: art, title, a two-sentence blurb, a Players / Time / Genre row, comps and the link; CSS subgrid lines the rows up across each row of cards.
- Print-and-play kits are on request: the PDFs stay in the repo, but pages link a "Request the kit" email instead of the file.

## Adding a game
Copy `games/dim-sum-rush/` to `games/<new-game>/`, update the copy and images, add its card to both `index.html` and `games/index.html`, add the page to `sitemap.xml`, add it to every game page's "More games" row, give its build a `?tutorial` deep link, and regenerate `assets/css/home-games.css`.

Game-page images over ~2x their display size have `-240/-480/-800/-1200` copies served through `srcset`; regenerate those copies whenever the full-size image changes.

## Stylesheet versions
Every page links its stylesheets with a content hash, e.g. `/assets/css/site.css?v=cf4b4e27`, so visitors get new CSS the moment it changes instead of a cached copy (GitHub Pages caches files for about 10 minutes). After editing any file in `assets/css/`, update the `?v=` on every page to the first 8 characters of the file's MD5 hash (`md5sum assets/css/site.css`).
